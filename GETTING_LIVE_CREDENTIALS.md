# Getting the Live Voice-Agent Details

## The Short Answer

You need **four things** before a real test call can happen: a LiveKit project, an Exotel account with a provisioned Indian caller number and SIP connectivity, a phone number you own for testing, and—later—a public URL for n8n. The agent software, dashboard, and n8n workflow file are separate from these provider accounts.

> **Important:** A real Indian phone call cannot be fully free. The agent software and n8n can be self-hosted, but a carrier must provide the phone number and minutes. Start with a single controlled call to your own number; do not enable a student campaign at this stage.

## Step 1 — Create LiveKit Credentials

Go to [LiveKit Cloud](https://cloud.livekit.io/), create an account, then create a project. In the project dashboard, open **Settings** or **Keys** and create a server API key. Save the following in a password manager; do not send them in ordinary chat.

| Value required by the project | Where it comes from | What it looks like |
| --- | --- | --- |
| `LIVEKIT_URL` | Your LiveKit project connection URL | Usually a `wss://...livekit.cloud` URL |
| `LIVEKIT_API_KEY` | A server API key created in LiveKit | A short project key |
| `LIVEKIT_API_SECRET` | The secret shown once when the server key is created | A long secret string |

LiveKit is the real-time room and agent layer. It is responsible for the continuous conversation, interruption handling, and connection of the carrier’s SIP audio to the agent. The project uses the official LiveKit Agents and telephony path. [1] [2]

## Step 2 — Open Exotel and Request the Right Product

Create an account at [Exotel](https://exotel.com/) or log in through the Exotel customer portal. For this project, tell the Exotel sales/support team exactly this:

> “I need a **controlled outbound AI voice-agent test** in India using **LiveKit SIP trunking**. I need an approved outbound caller ID, an outbound SIP trunk, and confirmation that the trunk can place an outbound call to my own Indian test number. Please provide the SIP trunk host, authentication details, allowed caller identity, and the provider callback/event method.”

Ask Exotel for the following items. Keep the SIP password private.

| Item from Exotel | What we use it for |
| --- | --- |
| Approved business caller number | This becomes `LIVEKIT_CALLER_ID`, in E.164 format, for example `+911140001234`. |
| Outbound SIP trunk host / proxy address | Entered into the LiveKit outbound SIP trunk configuration. |
| SIP username and password | Used to authenticate LiveKit to Exotel. |
| Confirmation of outbound SIP support | This is the gating condition for the preferred LiveKit path. |
| Provider status-callback format | Used to update ringing, answered, busy, no-answer, completed, and failed call records. |

Exotel documents both its real-time AgentStream path and a LiveKit SIP integration. The project’s primary design uses LiveKit SIP; direct AgentStream remains the fallback if Exotel cannot enable the outbound SIP route on your account. [3] [4]

## Step 3 — Create the Outbound SIP Trunk in LiveKit

After Exotel sends the SIP host and login, open LiveKit’s **Telephony / SIP** area and create an **outbound trunk**. Enter the Exotel host, username, password, and permitted caller number. LiveKit creates an outbound trunk identifier.

| Value required by the project | Where it comes from |
| --- | --- |
| `LIVEKIT_OUTBOUND_TRUNK_ID` | The outbound trunk ID generated by LiveKit after you save the Exotel SIP configuration. |
| `LIVEKIT_CALLER_ID` | The approved Exotel caller number, formatted as `+91...`. |

Do not use a personal number as caller identity unless Exotel has explicitly provisioned it for the account.

## Step 4 — Set Up Speech and Reasoning Services

You can begin by using LiveKit’s configured inference path, then evaluate voice quality before buying a premium voice plan. For a free-first evaluation, create accounts only after the LiveKit and Exotel steps are working.

| Capability | Free-first evaluation option | What you will eventually choose |
| --- | --- | --- |
| Speech-to-text | Create a [Deepgram](https://console.deepgram.com/) account and obtain an API key for streaming Hindi/English evaluation. | The provider/model that correctly transcribes real Indian-English and Hindi test recordings. |
| Text-to-speech | Use a LiveKit-compatible TTS integration for an initial test; compare voices with your approved college script. | The voice that sounds natural, pronounces programme names correctly, and supports interruption cancellation. |
| LLM | Use the configured LiveKit-compatible inference/provider account for initial bounded tests. | The model that follows tools and source boundaries reliably at acceptable latency. |

Do **not** buy a voice subscription first. Run a short evaluation with the same lines you expect the college agent to say: institution name, programme name, fee, callback question, and a Hindi interruption. The project’s TTS path already reformats currency and course abbreviations before speech; the final voice choice is about sound quality and latency.

## Step 5 — Create the Provider-Event Secret

Generate one random secret in your password manager, or on your own machine with:

```bash
openssl rand -hex 32
```

Store it as `LIVE_CALL_PROVIDER_EVENT_SECRET`. It protects the provider-status route so random internet traffic cannot mark a call as answered, failed, or completed. Do not send this value in normal chat; enter it through the secure project-secret form when requested.

## Step 6 — Choose the Controlled Test Number

Give us one number that **you own or directly control**, written in E.164 format such as `+919876543210`. This is not a provider credential, but it is required for the first test. The first live call should be only to this number. You will still confirm immediately before the dial action is enabled.

## Step 7 — n8n Comes Last

You already have n8n locally, which is fine. Do not connect it before the phone agent is working. Later, expose n8n at a public HTTPS URL such as `https://n8n.yourdomain.com`, import `n8n/voice-agent-events.workflow.json`, and copy its **production** webhook URL. n8n then receives post-call business events—callback requests, DNC requests, call failures, CRM tasks, and notifications. It never carries live call audio.

## What to Send Back Through the Secure Setup Form

When Steps 1–3 are ready, provide these six values through the secure project-secret card:

1. `LIVEKIT_URL`
2. `LIVEKIT_API_KEY`
3. `LIVEKIT_API_SECRET`
4. `LIVEKIT_OUTBOUND_TRUNK_ID`
5. `LIVEKIT_CALLER_ID`
6. `LIVE_CALL_PROVIDER_EVENT_SECRET`

In a normal message, provide only the controlled test number and confirm you are authorized to use it. Once those values are present, the next work is to validate the agent connection, run the voice/pronunciation evaluation, configure provider events, and prepare the final confirmed test call.
